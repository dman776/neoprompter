# Script model, Import, and the readable-color rule

Read this before touching how Scripts are stored, imported, edited, or colored.

## Script model

`src/core/types.ts` defines it: `Script { name, lines: ScriptLine[] }`. A `ScriptLine` is a plain `string` (one unstyled run) or a `RichLine { heading?: 1-6, runs: Run[] }`; a `Run` is `{ text, bold?, italic?, color? }`. Color is the source color as `#rrggbb`, stored as-is (the readable-color rule is applied at render time, never on the Script). Fonts, sizes and spacing are never stored. Use `lineRuns`/`lineText`/`lineHeading` to read a line. The library stores `StoredScript { text, lines? }`: `text` is the plain form, `lines` the optional styled form; old text-only entries still load. `saveScript` takes optional `lines`. The Output renders runs as spans, headings bold at the Preset's size.

## The Run mode lock

The core enforces it, whatever sends the command (editor, API, shuttle, menu). In Run mode it rejects every command that changes what the Talent reads: editing the loaded Script (`editLine`, `setScriptLines`, `cutLines`, `colorRange`) and the whole library (`saveScript`, `newScript`, `duplicateScript`, `loadScript`, `renameScript`, `deleteScript`), because loading, renaming or deleting replaces or detaches the live Script, and any other library change is a step towards one. Unlocking allows only `liveFix`, one paragraph's text. `src/core/lock.test.ts` is the rule in executable form. Import (File menu and header) is therefore Edit mode only: the menu item is disabled in Run mode and main answers with a plain message if asked anyway. The Operator view sends unsaved typing before it asks for a mode change (the editor saves 300 ms after typing), and says so plainly if the core did not keep it.

## Import

`src/import/`: `importDocx(bytes, fileName): { ok: true, script } | { ok: false, message }` is a pure function (the second test seam). Tests build `.docx` fixtures in code with `src/import/fixtures.ts`. `importDocx` resolves bold, italic and color through character styles, paragraph styles, `basedOn` chains and document defaults, with direct run formatting winning. Legacy `.doc` (Word 97-2003) goes through `importDoc` in `src/import/doc.ts`: a minimal pure-JS reader (the `cfb` package for the container; piece table, character/paragraph formatting and style sheet parsed in-house), same result shape; `.doc` fixtures are built in code by `src/import/docFixtures.ts`. Whitespace is kept as the file has it: no importer trims a line, collapses spaces or drops a blank line. (`.pdf` is the limit: it keeps what pdf.js reports, below.) A Word tab (`w:tab`, or 0x09 in a `.doc`) comes in as a tab character, and a Word line break or carriage return inside a paragraph (`w:br`, `w:cr`, 0x0B) starts a new line. The Output and the Live view draw the Script with `white-space: pre-wrap` and `tab-size: 4`, so leading spaces, repeated spaces and tabs show as typed (the editor already did). `importText` (`src/import/text.ts`) reads `.txt`: UTF-8 (BOM stripped) or UTF-16 with a BOM, one plain-string line per line (CRLF, CR and LF all split), blank lines kept, undecodable or all-blank files refused. `importPdf` (`src/import/pdf.ts`, ADR 0005) reads `.pdf` with `pdfjs-dist`: text only, no headings, emphasis or color. It joins lines that share a baseline, starts a new paragraph where the gap to the previous line is over 1.6 line heights (`PARAGRAPH_GAP`), and lets pages flow together with no page marker. Each line height of gap beyond the first becomes a blank line (at least one), so a gap between paragraphs shows as blank lines. Lines are joined with one space unless the PDF already has a space there, and the text is not trimmed or collapsed by the importer; pdf.js itself reports a run of spaces as one space, drops leading and trailing spaces and turns a tab into a space, so the file's exact spaces and tabs cannot be recovered. Password-protected, corrupt and image-only (scanned, no OCR) PDFs are refused with a message. It is async, so `importDocument(bytes, fileName)`, which dispatches by extension and is what main calls, returns a Promise. `.pdf` fixtures are built in code by `src/import/pdfFixtures.ts` (`makePdf`). pdf.js refuses a Node `Buffer`, so `importPdf` copies the bytes into a plain `Uint8Array`; it runs in main's bundle, loaded on the first PDF Import (not at startup), with the worker module handed over through `globalThis.pdfjsWorker`. At load pdf.js prints three warnings about canvas polyfills it only needs for drawing; `loadPdfjs` drops exactly those and nothing else. Not handled: multi-column layouts (text comes in stream order) and hyphenated line ends. `.doc` limits: Word 6/95 files and password-protected files are refused with a message; headings come from style names ("heading N", "Title") only, so text that is merely bold and large is not a heading; colors are the 16-color palette or 24-bit values (theme-based colors are lost); no list numbers, no text boxes, headers, footnotes or fields' results beyond their displayed text. Main wires the Operator view's "Import…" button (file picker for `.docx`, `.doc`, `.txt` and `.pdf`, then `saveScript` with `lines`).

## Watched folder

`src/watched-folder/`: one folder the Operator picks in Preferences (General), off until chosen; Word, text and PDF files (`.doc`, `.docx`, `.txt`, `.pdf`) dropped into it are Imported as Scripts. It reuses `importDocument` and the `saveScript` command, so it adds no way round the Run mode lock.

- `importWatchedFolder(folder, deps)` is one pass (the test seam, with a fake folder): each Word, text or PDF file is Imported, saved, and moved into the folder's `imported/` subfolder. Other file types, Word's `~$` lock files, hidden files and subfolders are ignored. A file that fails to Import stays where it is. A Script name already in the library gets the first free "<name> 2", "<name> 3" (`uniqueName`); a name already in `imported/` numbers the moved file. It does nothing outside Edit mode.
- A PDF takes a moment to read, so passes are async and `createFolderWatcher` runs them one after another: two at once would Import the same file twice. `setFolder` returns a promise for the first pass.
- `createFolderWatcher(deps)` runs passes: once when the folder is chosen or at startup (files that arrived while the app was closed), and again after a change, one `SETTLE_MS` later. A file is Imported only when its size and modified time are the same across two looks, so a file still being copied in is left alone. A file that failed is not tried or reported again until it changes. In Run mode nothing is saved and the files wait in the folder; on the change back to Edit mode the watcher checks again.
- The file system, the change source (`fs.watch`) and the timer are injected (`src/main/watchedFolderFs.ts` is the real set), so tests use a fake disk and a fake scheduler.
- The Operator is told through `describeResult`: a notice banner in the Operator view (`IPC.watchedFolderNotice`; a notice that arrives before the view is ready is held and handed over by `watchedFolderTakeNotice`), and the last result under the folder in Preferences. If the folder is gone, Preferences says so and nothing is attempted.
- The setting is `watched-folder.json` in the app's data folder (`createWatchedFolderSettings`, injected store and folder picker), like the Quick messages.
- Not done: several folders, subfolders, deleting dropped files.

## Readable-color guard

`src/core/readableColor.ts`: `displayColor(source, background, themeColor)` is a pure function the Output calls on every render for each colored run, so a background change re-evaluates every color. It keeps the source color if its WCAG contrast ratio against the Output background is at least `MIN_CONTRAST` = 3 (the WCAG large-text bar; prompter text is far larger, and 3:1 rejects Word's stray black, near-black and dark blue/red on black while keeping red and green), else returns the theme text color. Missing or invalid colors (anything but `#rgb`/`#rrggbb`) also use the theme color. The Operator view does not show Script text in color, so only the Output uses it.

## The readable-color rule in the editor

The rule applies wherever the Script is drawn, not only on the Output. The editor (Edit mode) shows a color that is too hard to read on its own background (3:1 contrast, the same `displayColor` as the Output) in the editor's text color instead, so black text from Word is never shown black on the dark look. It is a view-only ProseMirror decoration (`src/operator/readableColors.ts`): the document, the saved Script and the copied HTML keep the source color. The editor reads its background and text colors from the current look's tokens (`--surface`, `--text`) and checks again when the look changes.
